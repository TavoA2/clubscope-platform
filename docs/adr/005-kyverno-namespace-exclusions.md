# ADR 005: Exclude system namespaces from Kyverno resource-limit policy

## Status
Accepted

## Context
The `require-resource-limits` ClusterPolicy applied to all Pods across all namespaces with no exceptions. When provisioning a PersistentVolumeClaim for the `postgres` StatefulSet, the `local-path-provisioner` (running in `local-path-storage`) creates a short-lived, internally-generated "helper pod" to prepare the volume on the target node. This helper pod does not define resource requests/limits — it's generated by the provisioner itself, not user-authored — and was rejected by the policy's admission webhook, causing all PVC provisioning to fail cluster-wide.

## Decision
Add an `exclude` block to the policy, scoping enforcement away from namespaces that host cluster infrastructure the platform doesn't directly author: `kube-system`, `local-path-storage`, and `kyverno` itself.

## Consequences
**Positive:**
- PVC provisioning (and any other infrastructure component relying on internally-generated pods) works correctly again
- Policy still fully enforced for all application workloads in `default` and any future app namespaces

**Negative / trade-offs accepted:**
- Excluded namespaces are now unprotected by this policy — acceptable here since these are trusted, cluster-managed components, not user-deployed workloads
- Any future infrastructure component installed into a new system namespace would need this exclusion list revisited — a broader long-term solution would be an allow-list approach (only enforce in explicitly labeled app namespaces) rather than a deny-list of exclusions
